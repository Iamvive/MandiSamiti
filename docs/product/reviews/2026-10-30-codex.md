## Delivered

- D7 normalizes party phones to the last 10 digits and enforces one non-null phone per shop.
- New-party UI requires a valid phone. A duplicate shows the existing party and offers to open its ledger.
- Phone-less auto-provisioned parties remain valid, show a warning badge, and can add a phone from the Khata list.
- Party selection persists the party UUID across buy, sell, and lend flows; lists and edit forms resolve the UUID back to the display name.
- Party pickers no longer hide a person by FARMER/BUYER role.
- D8 allocates farmer receipt numbers per farmer and sell/lend numbers per shop. Voids and edits retain the number; numbering never resets by date.
- Assigned numbers appear in buy, sell, and lend lists, receipts, search, and the party ledger. Older rows fall back to a short ID.
- Buy and sell receipts show date/time, shop, mandi, and party village when available.

## Schema and query changes

Only `core-database/src/commonMain/sqldelight/com/appwork/mandisamiti/database/AppDatabase.sq` changed. No `.sqm` migration was added.

- `partyEntity`: unique index `idx_party_shop_phone(shop_id, phone)`.
- `buyEntryEntity`: nullable `slip_no INTEGER`.
- `sellEntryEntity`: nullable `slip_no INTEGER`.
- `lendEntryEntity`: nullable `slip_no INTEGER`.
- Party queries: `updateParty`, `getPartyByIdAny`, `getPartyByPhone`, `insertPartyFromServer`.
- Slip allocators: `nextFarmerSlipNo`, `nextSellSlipNo`, `nextLendSlipNo`.
- Insert and server-apply queries carry `slip_no` for buy, sell, and lend rows.

SQLDelight uses the SQLite 3.18 dialect, so the planned `ON CONFLICT(id) DO UPDATE` syntax could not compile. The equivalent safe implementation uses separate plain `INSERT` and `UPDATE WHERE id` queries; duplicate phone inserts raise instead of replacing another party.

## Sync contract for Claude

`BuyEntrySyncDto`, `SellEntrySyncDto`, and `LendEntrySyncDto` now expose:

```text
slip_no: Long? = null
```

`SyncEngine` maps the field in both directions. The backend still needs Claude's nullable integer columns and schemas. Until that backend work lands, the updated client contract and old server contract are not expected to round-trip `slip_no`.

Server phone collisions now fail and roll back the pull page so the cursor cannot advance past a silently ignored party.
