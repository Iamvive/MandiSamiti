# Codex K1 handoff: pilot client schema freeze

## Result

The pilot client schema is frozen at SQLDelight version 7. Migration `6.sqm` upgrades the last represented schema, version 6, without dropping or renaming anything.

## Schema audit

Before K1, the committed migration chain was `1.sqm` through `5.sqm`, so SQLDelight's real migrated version was 6. `AppDatabase.sq` contained four schema changes not represented by that chain:

| Object | Missing change | Version-6 row default |
| --- | --- | --- |
| `partyEntity` | Unique index `idx_party_shop_phone(shop_id, phone)` | Not applicable |
| `buyEntryEntity` | Nullable `slip_no INTEGER` | `NULL` |
| `sellEntryEntity` | Nullable `slip_no INTEGER` | `NULL` |
| `lendEntryEntity` | Nullable `slip_no INTEGER` | `NULL` |

There were no missing tables. The D4 settlement split, calculated interest, payment modes, and `dayClosingEntity` were already covered by `4.sqm` and `5.sqm`.

## Changes

- Added additive `core-database/.../6.sqm` for the four missing changes.
- Generated and committed `databases/7.db` with `generateCommonMainAppDatabaseSchema`; it completed once in 1 second under a 120-second timeout.
- Added `PilotSchemaMigrationTest`. It copies committed `1.db`, migrates it to version 6, inserts one row into every one of the 13 tables, migrates to version 7, and checks:
  - every row count is unchanged;
  - representative `Long` paisa values are unchanged;
  - all three new `slip_no` values default to `NULL`;
  - the party phone unique index exists.
- Added `core-database/MIGRATIONS.md` with the immutable migration and snapshot workflow.

## Missing-migration proof

I temporarily removed `6.sqm` and ran:

```text
./gradlew :core-database:jvmTest --tests com.appwork.mandisamiti.database.PilotSchemaMigrationTest
```

The test failed at its schema-version assertion because the generated schema was version 6 instead of version 7. I then restored `6.sqm`.
